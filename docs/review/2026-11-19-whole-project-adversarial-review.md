# 전체 적대적 검토 (W4 이후)

W4까지 병합한 main(`152dd87`)의 코드·문서·설계 전체를 다시 검토했다. 기존 테스트는 모두 통과하는
상태였지만 높음 등급 결함이 여섯 건 있었다. 다섯 건은 사용자가 직접 겪는 결함이다. 그중 하나는 보안 결함으로,
허브용 등록 코드를 본 사람이 휴대폰 권한 토큰을 받아 차고문을 열 수 있었다. 나머지 넷은 음성 명령과 알람의
신뢰성 결함이다. 예를 들어 "매일 7시 알람 끄지마"라고 말하면 매일 알람이 새로 생겼고, 앱을 강제 종료한 뒤에는
화면에 켜져 있다고 표시된 알람이 울리지 않았다. 여섯 번째는 승인된 ADR 0004가 다른 커밋에 섞여 삭제된 것이다.
높음과 중간·낮음 항목은 같은 날 고쳐 병합했다. LAN 구간 암호화는 방식을 먼저 정해야 해서 #89로 남긴다.

## 검토 요약

- 대상: main `152dd87`의 `server/`, `hub/`, `protocol/`, `docs/`, `scripts/`, `.github/`, `.githooks/`, `infra/`, `spikes/`
- 방법: 영역별로 나눈 서브에이전트 4개가 결론을 받지 않은 채 코드만 읽고 읽기 전용으로 검토했다. 영역은 서버
  코어·보안, 에이전트·음성·프로토콜, 허브 앱, 문서·설계·프로세스다. 높음·중간 항목은 Claude가 코드를 다시
  읽거나 서버 가상환경에서 직접 재현해 확인했다. 확인하지 못한 항목은 표에 그렇게 적었다.
- 위협 가정: [서버 보안 검토](2026-11-19-server-security-review.md)와 같다. LAN 손님 기기, 도난된 휴대폰 토큰,
  TV·방문자 음성이다. 여기에 반쯤 끊긴 Wi-Fi 연결, 재부팅·강제 종료·시각 변경 같은 태블릿 운영 상황을 더했다.
- 제외한 지적: 문서 검토에서 나온 "설계안 0005가 말하는 `agent/understand/`·`agent/skills/`가 없다"는 지적은
  사실이 아니었다. 두 디렉터리 모두 있다.

## 조치와 잔여 위험

높음과 중간·낮음 항목은 다섯 묶음으로 고쳐 2026-11-19에 병합했다. 묶음마다 회귀 테스트를 넣었고, push 전 훅이
로컬 `scripts/verify.sh`를 통과시켰다. 개발 서버 배포와 실기기 확인은 아직 하지 않았다.

| 묶음 | 대상 | 조치 | 남은 위험 |
|---|---|---|---|
| #90 | #78, #83 | 등록 코드에 종류를 묶고 `/pair`는 그 종류만 발급한다. 음성 경로에서 `device_class` 없는 커버 열기를 막는다. 장면은 `COZY_ALLOWED_SCENES`만 허용하고, `COZY_VOICE_BLOCKED_ENTITIES`는 도메인과 무관하게 막는다 | 문을 여는 switch는 운영자가 `COZY_VOICE_BLOCKED_ENTITIES`에 등록해야 막힌다. 출입문 터치 제어 허용은 서버 보안 검토의 잔여 위험 그대로다 |
| #91 | #87 | `poetry.lock`에서 해시 고정 파일을 만들어 이미지에 설치한다. nginx 컨테이너 읽기 전용·capability 제한, `/ws` 핸드셰이크 속도 제한, 종료 유예 70초를 넣는다. `verify.sh`는 공용 스크립트 변경 때 모든 컴포넌트를 검사하고, 비밀정보 검사 패턴을 넓히고, 절대경로를 제거한다 | nginx 읽기 전용 실행은 Docker에서 확인하지 않았다. HA·matter 이미지 `:stable` 태그 고정도 남았다(#87) |
| #92 | #79, #80, #85 | 부정 표현과 미지원 날짜어가 있으면 결정론 파서가 처리하지 않고 LLM으로 넘긴다. 라벨 지정 취소는 라벨 있는 알람끼리만 일치한다. 턴 취소·예외 경로를 정리하고, 허브를 모르는 연결의 대화 상태를 연결별로 나눈다 | 결정론 파서가 넘긴 표현을 LLM이 맞게 처리하는지는 실사용 턴 기록으로 확인한다 |
| #93 | #82, #84 | 방송은 연결별로 동시에 보내고 송신에 5초 제한을 둔다. HA 이벤트는 큐로 분리한다. REST 방송에 호출자별 한도를 두고 `from_hub_id`는 관리자만 쓴다. 허브 거절은 `rejected`로 표시하고 사본을 허브 값으로 되돌린다. 음성 알람은 허브 확인을 최대 3초 기다려 답한다 | 음성 알람 응답이 최대 3초 늦어질 수 있다 |
| #94 | #81, #86 | 허브 앱은 시작할 때 알람을 다시 예약하고, 스누즈 중인 일회성 알람을 유지한다. 사설망 판별을 고치고, 마이크를 다시 열고, 재접속 대기는 30초 이상 유지된 연결에서만 초기화한다 | 강제 종료·재부팅·마이크 점유 상황의 실기기 확인은 #13에 추가했다 |
| 이 문서와 함께 | #88 | ADR 0004를 복원하고, README와 설계안 0001·0002·0006을 정정하고, [현행 아키텍처](../architecture/README.md)를 새로 쓴다 | 설계안 0002의 MCP 연동을 버리고 HA WebSocket API로 구현한 판단의 근거가 기록돼 있지 않다 |

LAN 구간 암호화(#89)는 이번에 고치지 않는다. Tailscale 전용으로 갈지, 사설 인증서와 허브 인증서 고정으로 갈지를
먼저 정해야 한다. 그 전까지 같은 Wi-Fi에 붙은 기기는 토큰과 음성을 가로챌 수 있다.
