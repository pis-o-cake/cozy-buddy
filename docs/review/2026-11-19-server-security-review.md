# 서버 보안 검토 (W3 이후)

W3로 허브 페어링·방송·리마인더가 들어온 뒤, 서버의 인증·입력 한도·비용·기기 제어 경로를 검토했다. 가장 큰
결함은 REST 일부가 인증 없이 열려 있던 것이다. 같은 Wi-Fi에 붙은 누구나 가족 대화 전사 30일치를 읽고 허브
설정을 바꿀 수 있었다. 이 결함과 WebSocket 한도, OpenAI 비용 상한, 위험한 HA 제어는 모두 고쳐서 개발 서버에
배포했다. 남은 위험은 아래 조치 표의 마지막 열에 적었다.

## 검토 요약

- 대상: main의 `server/` 코드, nginx 설정, Docker Compose, 비밀정보 차단 스크립트
- 방법: 구현에 참여하지 않은 서브에이전트가 결론 없이 코드만 받아 읽기 전용으로 검토했고, 높음·중간 항목은
  Claude가 코드 경로를 다시 확인했다. 수정은 두 묶음(#72, #73)으로 나눠 병합했다.
- 위협 가정: LAN 손님 기기, Tailscale을 공유받은 노드, 도난된 휴대폰 토큰, TV·방문자 음성을 통한
  프롬프트 주입. 공인 포트는 열지 않는다([서버 설계안](../design/0002-server-architecture.md) 배포 절).

## 발견 사항

| 등급 | 결함 | 영향 |
|---|---|---|
| 높음 | `/api/hub`(조회·변경), `/api/alarm`, `/api/system/turns`에 인증 없음. `/docs`도 공개 | 가족 발화 전사 30일치 노출, 허브 방(area) 변경으로 방송 대상 조작 |
| 높음 | `/ws`가 인증 전에 연결을 받고 연결 수·첫 프레임 크기·hello 실패 횟수 제한이 없음 | 미인증 메모리 압박, 약한 정적 토큰의 온라인 대입 |
| 중간 | 인증된 클라이언트의 텍스트 질의 길이·동시 수·턴 수, 리마인더 TTS에 상한이 없음 | 도난 토큰 하나로 OpenAI 비용 무제한 |
| 중간 | HA 노출 목록을 못 읽으면 허용 도메인 전체가 제어 대상이 됨 | 노출하지 않은 커버·스크립트까지 음성·LLM으로 제어 |
| 중간 | 음성·LLM으로 차고문·대문 커버 열기, 임의 HA 스크립트 실행 가능 | 오인식이나 프롬프트 주입으로 출입문 개방 |
| 낮음 | 발급 모바일 토큰이 방송 REST에서 거부됨, x-request-id 무검증, 키·DB 파일 gitignore 누락, 컨테이너 권한 기본값 | 관리자 토큰을 앱에 넣는 우회 유도, 로그 오염, 실수 커밋 |

잠금 해제(`lock`)와 경보 패널(`alarm_control_panel`)은 처음부터 서비스 호출 화이트리스트에 없어 제어할 수
없었다. 토큰은 SHA-256 해시만 저장하고 상수 시간으로 비교하며, 허브 전용 메시지는 연결의 `client_id`로
묶여 다른 허브를 사칭할 수 없다.

## 조치와 잔여 위험

| 결함 | 조치 | 남은 위험 |
|---|---|---|
| REST 무인증 | 모든 도메인 라우터 기본 거부, `/api/system/*` 관리자 전용, 문서 UI 기본 꺼짐 (#72) | 없음 |
| `/ws` 한도 | 첫 프레임 4KB, IP별 hello 실패 60초 10회 차단, 연결 64개·IP별 미인증 8개, 메시지 1MiB, nginx 속도 제한 (#72, nginx 반영 확인) | 허브가 한 NAT 뒤에 16대를 넘으면 nginx IP당 연결 상한을 올려야 한다 |
| 약한 정적 토큰 | `change-me`가 남은 토큰은 시작 거부, 24자 미만은 경고 (#72) | 개발 서버 토큰 길이는 확인하지 않았다(`.env` 비열람 원칙) |
| 비용 상한 | 텍스트 300자, 연결당 진행 중 질의 1건, 클라이언트별 분당 20턴, 하루 LLM 1500회·TTS 10만 자·STT 7500초 (#73) | 한도는 가족 300턴×5 추정치다. 실사용 턴 기록으로 다시 맞춘다 |
| 노출 목록 폴백 | 목록을 못 읽으면 제어는 조명·스위치·선풍기만 (#73) | 없음 |
| 출입문·스크립트 | 차고문·대문·현관 커버는 음성·LLM 제어 금지, 스크립트는 `COZY_ALLOWED_SCRIPTS`만 (#73) | 출입문 커버의 터치 제어는 허용했다. 휴대폰 토큰이 도난되면 원격으로 열 수 있으므로, 앱 출시 전에 막을지 다시 정한다 |
| 낮음 항목 | 모바일 발급 토큰 허용, request-id 검증, gitignore, `no-new-privileges`·`cap_drop` (#72) | 컨테이너 `read_only`는 쓰기 경로 확인 전까지 보류. 프롬프트 주입으로 방송을 보내게 하는 경로는 턴 제한 외에 별도 승인이 없다 |
