# S2 음성 경로 비교: OpenAI 단계별 API 대 실시간 음성 모델

합성 음성으로 한국어 명령 50개를 측정했다. 실시간 음성 모델(B)은 첫 소리가 약 1.2초 빨랐다(p50 1.77초,
단계별은 2.95초). 대신 정확도는 약간 낮았고 비용은 2.4배였다. 또 발화 전사문을 주지 않아 오류 원인을
가를 수 없었고, 알람 시각을 틀리게 설정한 사례가 나왔다. 단계별 경로(A)의 지연은 대부분 LLM 두 번
왕복에서 생긴다. 서버 설계의 결정론 매처가 짧은 명령을 처리하면 이 구간이 빠진다. 그래서 **단계별 경로 +
결정론 우선 처리**를 기본 방향으로 잡는다. 확정은 실제 사람 음성으로 다시 측정한 뒤 ADR로 한다.

## 결론과 적용 범위

- 기본 방향: STT → 결정론 매처 → (매칭 실패 시) 경량 LLM 툴 루프 → TTS. 실시간 음성 모델은 자유 대화 모드
  후보로만 남긴다.
- 근거 세 가지:
  - 단계별 경로는 전사문을 남긴다. 그래서 결정론 매처, 오류 분석, 확인 질문 정책을 적용할 수 있다.
  - 실시간 모델은 알람 범주 정확도가 0.5였다. "오후 3시 30분"을 07:30으로, "저녁 8시"를 22:00으로 설정했다.
    알람은 틀리면 안 되는 기능이다.
  - 명령당 비용이 단계별 $0.0016, 실시간 $0.0038이다.
- 이 결론이 적용되는 범위:
  - OpenAI 모델 `gpt-4o-transcribe`, `gpt-5.4-nano`, `gpt-4o-mini-tts`, `gpt-realtime-2.1-mini`
  - 합성 음성 입력
  - 개발용 Mac의 네트워크 위치
  - 실제 사람 음성, 태블릿 마이크, 허브 네트워크에서 같은 차이가 나는지는 이 실험으로 말할 수 없다.
- 결정론 처리 시 지연은 측정하지 않았다. 다만 A의 STT 시간(p50 0.68초)에 TTS 첫 바이트 시간을 더한 값이 될
  것으로 본다. 후속 측정 대상이다.

## 실험 조건

- 하네스: `spikes/s2-voice-path/` (`uv run python -m s2 run --paths a,b --repeat 3`), 결과
  `spikes/s2-voice-path/results/20261113T064253Z/`(`raw.jsonl` 300건, `summary.json`).
- 명령 세트: `commands.jsonl` 50개와 기대 툴 호출.
  - 명시적 방 10, 암시적 방(거실) 7, 구어체 5, 밝기 7, 상태 질의 5, 알람 4, 타이머 3, 기기 2개 동시 4, 잡담 5.
  - 가짜 집(거실·침실·주방)에 툴 4종(`control_device`, `get_device_state`, `set_alarm`, `set_timer`)을 두었다.
- 입력 음성: `gpt-4o-mini-tts`의 echo 음성으로 합성했다. 24kHz mono PCM16.
- A 단계별:
  1. `gpt-4o-transcribe`(language=ko)로 전사한다.
  2. `gpt-5.4-nano`(`reasoning_effort=none`)가 스트리밍으로 툴을 호출한다. 결과는 `role: tool`로 넣고 마지막 턴을
     스트리밍한다.
  3. 문장 단위로 `gpt-4o-mini-tts`(coral, PCM)에 넘긴다.
  4. t0는 오디오 업로드 시작이다.
- B 실시간: `gpt-realtime-2.1-mini`.
  - 서버 VAD를 끄고 오디오를 미리 보낸 뒤 수동으로 commit한다.
  - 같은 가짜 툴 실행기로 함수 호출을 처리한다.
  - t0는 commit 전송 시점이다.
- 순차 실행, 샘플 간격 0.5초, 재시도 1회, 타임아웃 60초. 실행 위치는 개발용 Mac(한국)이다.
- 정확도 기준: 툴 이름과 필수 인자가 모두 기대와 같아야 맞은 것으로 센다. 잡담은 툴을 호출하지 않아야 맞다.
- 비용: https://developers.openai.com/api/docs/pricing (2026-11-13 조회) 기준이다. `gpt-4o-mini-tts`는 분당
  가격이 게시되지 않아 분당 $0.015로 가정했다.

## 결과

경로당 150건(명령 50개 × 3회)이며 실패는 0건이다. 총 추정 지출은 $0.81이다.

| 지표 | A 단계별 | B 실시간 |
|---|---|---|
| 발화 종료 → 첫 소리 p50 | 2.95초 | 1.77초 |
| 발화 종료 → 첫 소리 p95 | 3.61초 | 2.54초 |
| 완료 p50 | 3.98초 | 3.26초 |
| 툴 명령 정확도 | 86.7% | 83.7% |
| 잡담 무툴 정확도 | 100% | 100% |
| 전체 정확도 | 88.0% | 85.3% |
| 명령당 추정 비용 | $0.0016 | $0.0038 |

A의 구간별 시간:
- STT: p50 0.68초, p95 0.92초.
- LLM 첫 토큰: STT 완료 후 p50 0.65초.
- 나머지 시간은 툴 실행 후 두 번째 LLM 턴과 TTS 첫 바이트다.

범주별 정확도(A / B):

| 범주 | A | B |
|---|---|---|
| 알람 | 1.0 | 0.5 |
| 타이머 | 0.67 | 0.67 |
| 상태 질의 | 0.73 | 0.6 |
| 암시적 방 | 0.71 | 0.86 |
| 밝기 | 0.86 | 1.0 |
| 명시적 방 켜기/끄기 | 0.93 | 0.87 |
| 구어체, 기기 2개 | 1.0 | 1.0 |

A의 오류는 대부분 STT 오인식에서 나왔다. 전사문이 정답과 정확히 같은 비율은 69%였다. 숫자와 문장부호
표기 차이를 빼도 실제 오인식이 남는다. 예:

| 정답 | 전사 결과 |
|---|---|
| 불 좀 켜줄래 | 불 좀 타줄래? |
| 지금 불 꺼 | 벵골어·체코어 문장 |
| 주방 조명 | 후방 조명 |
| 침실 조명 | 충실충력 |
| 침실 가습기 | 심의실 가습기 |
| 5분 타이머 | 밥인 타이머 |

LLM 판단 오류도 있었다. "주방 전기포트 켜줘"의 전사문 "켜져."를 상태 질의로 처리했다.

B는 입력 전사문을 받지 않아 오인식과 판단 오류를 나눌 수 없다. 오류 예:
- "주방 조명 꺼"를 켜기로 호출했다.
- "5분 타이머"를 30분으로 설정했다.
- "지금 불 꺼"에서 툴을 호출하지 않았다.

B의 응답 문장은 시스템 프롬프트의 1~2문장 제한보다 길어지는 경향이 있었다.

## 한계와 후속 조치

- 입력이 모두 합성 음성 한 종류다.
  - 짧고 빠른 합성음 때문에 오인식이 실제보다 과장됐을 수 있다.
  - 반대로 잡음이 없어 실제 마이크보다 유리했을 수도 있다.
  - 사람 음성 재측정 전에는 정확도 수치를 기능 판단 근거로 쓰지 않는다.
- 같은 오디오를 3번 썼으므로 150건은 서로 독립된 표본이 아니다. p95는 이 점을 감안해 읽는다.
- t0 정의가 두 경로에서 다르다. B는 오디오 업로드 시간이 지연에 포함되지 않았다. 실사용에서는 두 경로
  모두 VAD 종료 판정 시간(가설상 0.5~0.8초)이 더해진다.
- 측정 위치가 개발용 Mac이다. 허브 실기기와 상시 서버의 네트워크 지연은 다를 수 있다.
- 후속 측정(S2b):
  1. 소유자가 `record` 하위 명령으로 사람 음성을 녹음해 50개를 다시 측정한다.
  2. STT에 집의 기기·방 이름을 `prompt`로 넣어 오인식이 줄어드는지 측정한다.
  3. 결정론 매처 + 템플릿 TTS 경로의 첫 소리 지연을 측정한다.
  4. 결과로 음성 경로 ADR을 작성한다.
