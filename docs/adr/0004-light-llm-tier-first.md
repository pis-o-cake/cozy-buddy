# LLM은 경량 모델로 시작하고 부족할 때 올린다

대화 에이전트의 LLM은 OpenAI GPT 계열 중 경량 등급 모델로 시작한다. Google로 치면 Flash-Lite에 해당하는
등급이다. 품질이 부족하다고 판단되면 상위 등급으로 올린다. 모델 이름은 코드에 넣지 않고 설정값으로만 지정한다.
따라서 등급을 바꿀 때 코드는 고치지 않는다.

## 결정

- 기본 모델은 OpenAI의 경량 등급(mini·nano 계열)이다. 구체적인 모델 이름은 스파이크 S2 시점에 OpenAI가
  제공하는 경량 모델 가운데 툴 호출을 지원하는 것으로 정한다.
- 모델 이름은 서버 설정(`.env`의 `OPENAI_LLM_MODEL`)으로만 지정한다. 코드에는 기본값을 두지 않고, 설정이
  없으면 서버가 시작 단계에서 실패한다.
- 상위 등급으로 올리는 기준은 S2와 첫 루프 사용 기록에서 확인한다. 하나는 기기 제어 툴 호출의 오작동이고,
  다른 하나는 한국어 응답 품질에 대한 가족의 불만이다.
- 실시간 음성 모델을 쓰게 되면(S2 결과) 같은 원칙을 적용한다. 경량 등급(mini 계열)부터 시작하고 모델
  이름은 설정으로 둔다.

## 배경과 제약

[ADR 0003](0003-openai-as-llm-provider.md)으로 공급자를 OpenAI로 정했지만 모델 등급은 정하지 않았다.
허브의 대부분 요청은 짧은 기기 제어와 알람 설정이다. 이런 요청은 서버의 결정론 매처가 먼저 처리하고,
LLM은 나머지를 맡는다([서버 설계안](../design/0002-server-architecture.md)). 프로젝트 소유자는 경량 모델로
시작하고, 성능이 부족할 때만 올리기로 정했다.

## 근거와 대안

| 대안 | 판단 |
|---|---|
| 경량 등급으로 시작 (채택) | 응답 지연과 비용이 가장 낮다. 짧은 명령과 툴 호출 위주인 사용 패턴에 맞는다 |
| 처음부터 상위 등급 | 품질 여유는 크지만, 부족하다는 근거가 없는 상태에서 지연과 비용을 먼저 치른다 |
| 요청 종류별로 등급 분리(라우팅) | 짧은 명령은 이미 결정론 매처가 처리하므로 LLM 안에서 다시 나눌 이유가 아직 없다. 상위 등급이 필요해질 때 다시 검토한다 |

## 영향

- 서버 설정에 `OPENAI_LLM_MODEL`이 필수 항목으로 추가된다. 등급 변경은 `.env` 수정과 서버 재시작으로 끝난다.
- 경량 모델은 복잡한 다단계 요청에서 툴 선택을 잘못할 가능성이 더 크다. S2에서 한국어 명령 세트로 툴
  정확도를 측정하고, 실패 사례를 등급 승격 판단의 근거로 남긴다.
