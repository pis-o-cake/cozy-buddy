# 클라우드 LLM 공급자는 OpenAI로 한다

대화 에이전트의 LLM은 OpenAI GPT 모델을 쓴다. 음성 경로 스파이크 S2는 OpenAI가 제공하는 선택지 안에서
비교한다. 단계별 API(STT → GPT → TTS)로 이을지, 실시간 음성 모델 하나로 처리할지를 이 범위에서 고른다.
구체적인 모델 이름은 S2 결과로 정한다.

## 결정

- LLM 공급자는 OpenAI다. API 키는 레포 루트의 `.env`(`OPENAI_API_KEY`)에만 두고 커밋하지 않는다.
  레포가 공개 저장소이므로 키 노출 방지가 특히 중요하다.
- STT와 TTS도 S2에서 OpenAI 선택지를 먼저 측정한다. 한국어 품질이나 지연이 기준에 못 미치는 항목만 다른
  공급자를 추가로 검토한다.
- 공급자 연동 코드는 OpenAI 하나만 구현한다. 공급자를 바꿔 끼우는 인터페이스는 두 번째 공급자가 실제로
  필요해질 때 추출한다.

## 배경과 제약

[ADR 0001](0001-cloud-only-ai-inference.md)로 AI 추론을 클라우드로 정했지만 공급자는 비워 두었다.
[검토 보고서](../review/2026-11-13-legacy-design-adversarial-review.md)는 S2에서 여러 공급자의 실시간 음성
API를 비교하자고 했다. 그러나 공급자마다 키·과금·데이터 정책을 따로 준비해야 하고, 이 비용이 측정
시작을 늦춘다. 프로젝트 소유자는 LLM으로 GPT를 쓰기로 정하고 OpenAI 키를 제공했다.

## 근거와 대안

| 대안 | 판단 |
|---|---|
| OpenAI 단일 공급자 (채택) | 키 하나로 LLM, STT, TTS, 실시간 음성 모델을 모두 측정할 수 있다. 소유자가 이미 사용 중이다 |
| 여러 공급자 비교 후 선택 (Gemini, Claude 등) | 공급자별 준비 비용이 들고, 소유자가 GPT로 정했으므로 비교의 실익이 작다 |
| 단계별로 다른 공급자 조합 | 측정 전에 조합을 정할 근거가 없다. S2에서 OpenAI 항목이 기준 미달일 때만 검토한다 |

## 영향

- S2 비교 대상이 OpenAI 단계별 API 조합과 OpenAI 실시간 음성 모델로 좁혀진다.
- 데이터 처리 정책(보존 기간, 학습 사용 여부)은 OpenAI API 정책을 따른다. 모델 종료와 가격 변경도 OpenAI
  일정에 맞춰 따라가야 한다.
- 이 키는 대화창에 붙여 넣어진 적이 있다. 노출이 의심되면 OpenAI 콘솔에서 폐기하고 `.env`만 교체한다.
  코드 변경은 필요 없다.
